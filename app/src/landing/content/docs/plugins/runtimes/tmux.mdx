Maestro uses [tmux](https://github.com/tmux/tmux) as the default runtime on macOS and Linux. Each session lives in its own tmux window under a single Maestro-managed session, and you can attach to any of them interactively.

## Install

macOS:

```bash
brew install tmux
```

Debian/Ubuntu:

```bash
sudo apt install tmux
```

Arch:

```bash
sudo pacman -S tmux
```

Maestro needs tmux 3.2 or newer.

## Use

```yaml title="maestro.yaml"
runtime: tmux
```

No plugin-level config — this is the default on macOS/Linux so you can also omit the key entirely.

## How it works

- Every Maestro-managed process lives in a tmux window inside a per-project tmux session.
- Agents start via `tmux send-keys` so their output is captured.
- For long commands (>200 characters), Maestro writes a temp bash script and sources it, because `tmux send-keys` truncates paste buffers.

## Attaching

```bash
maestro session attach <sessionId>
```

Or from inside tmux, switch windows manually. You can detach at any time (`Ctrl-b d`) and Maestro keeps running.

## Troubleshooting

- **`tmux server not running`.** `maestro start` launches the server for you; if you killed it, run `maestro start` again.
- **Window disappears after agent exits.** Intentional — Maestro cleans up finished windows. The session metadata is archived under `~/.maestro/.../archive/`.
