## From `@composio/maestro` to `@tinhtran/to`

The npm scope moved to `@tinhtran/to`. If you installed under the old name:

```bash
npm uninstall -g @composio/maestro
npm install -g @tinhtran/to
```

Your config and data directory (`~/.maestro`) don't change — no data migration needed. GitHub org and repo URLs (`ComposioHQ/maestro`) didn't change either.

## `maestro spawn <project> <issue>` → `maestro spawn <issue>`

The old two-argument form is rejected with an error. Pick the project via `-p` or by running from inside its worktree:

```bash
# old
maestro spawn myproject 42

# new
maestro spawn 42 -p myproject
# or, from inside the project's worktree:
maestro spawn 42
```

## `maestro init` → `maestro start`

`maestro init` has been removed. Use `maestro start` instead; it auto-creates `maestro.yaml` on first run and opens the dashboard in one step.

## Upgrading

Preferred:

```bash
to update
```

The command detects your install method (`npm-global`, `pnpm-global`, git, or unknown) and picks the right upgrade path. Override behaviour with `--skip-smoke` or `--smoke-only` for git installs.

## Before major upgrades

1. `maestro status` — see what's running.
2. `maestro session cleanup` — archive finished sessions.
3. `maestro stop --all` — halt every Maestro instance.
4. Upgrade.
5. `maestro doctor` on the new version.
